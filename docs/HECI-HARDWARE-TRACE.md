# HECI / Intel ME Hardware Trace (Skylake)

Цей документ містить задокументовану фізичну реальність (HARDWARE VIEW) взаємодії з пристроєм HECI (Intel Management Engine Interface). Він створений на основі реальних дампів із Kali Linux (на "голому залізі") для того, щоб слугувати еталоном для написання драйвера в MINIX 3 та створення мок-пристрою в QEMU.

## 1. Апаратний контекст
- **Платформа:** Intel Core i5-6400 (Skylake / Sunrise Point)
- **PCI ID:** `8086:a13a` (HECI Controller)
- **Прошивка ME:** `11.8.50.3425`

## 2. Протокол MKHI (Байти запитів/відповідей)

Знято за допомогою `mei-observer` через `/dev/mei0`. Всі комунікації використовують протокол MKHI (`protocol_version=1`, `max_msg_length=2048`).

### 2.1. Отримання версії прошивки (FW Version)
- **Запит (4 байти):** `ff 02 00 00`
  *(group_id=0xff, command=0x02)*
- **Відповідь (28 байт):** `ff 82 00 00 08 00 0b 00 61 0d 32 00 08 00 0b 00 61 0d 32 00 08 00 0b 00 61 0d 32 00`
  *(group_id=0xff, command=0x02, result=0x00)*
- **Інтерпретація:** 11.8.50.3425 (Code, Recovery, FITC).

### 2.2. Отримання можливостей (FW Caps SKU)
- **Запит (8 байт):** `03 02 00 00 00 00 00 00`
  *(group_id=0x03, command=0x02)*
- **Відповідь (13 байт):** `03 82 00 00 00 00 00 00 04 40 11 10 31`
  *(group_id=0x03, command=0x02, result=0x00)*
- **Інтерпретація:** raw=`0x31101140` (manageability=0, pavp=0).

### 2.3. Стан функцій (FW Feature State)
- **Запит (8 байт):** `03 02 00 00 20 00 00 00`
- **Відповідь (13 байт):** `03 82 00 00 20 00 00 00 04 40 11 10 11`
- **Інтерпретація:** raw=`0x11101140` (PTT=0, PSR=0).

## 3. Сила взаємодії з MMIO (Register Trace)

Знято через ftrace (`heci-fw-version.trace`). Це точна послідовність звернень до регістрів BAR0, яку робить ядро для ініціалізації пристрою та передачі даних.

```text
1. Читання H_D0I3C [0x800] -> 0x6
2. Запис H_D0I3C   [0x800] <- 0x2
3. Читання H_CSR   [0x4]   -> 0x80000069
4. Запис H_CSR     [0x4]   <- 0x80000008 (Ініціалізація / Reset)
5. Читання H_CSR   [0x4]   -> 0x80000048
6. Запис H_CSR     [0x4]   <- 0x80000048
7. Читання ME_CSR_HA [0xc] -> 0x80000009 (Перевірка статусу з боку ME)
8. Читання ME_CSR_HA [0xc] -> 0x80000009
9. Запис H_CSR     [0x4]   <- 0x8000002d (Підтвердження готовності хоста)
10. Читання ME_CSR_HA [0xc] -> 0x8000000b (ME підтверджує готовність)
```

Ці адреси регістрів (`H_CSR=0x4`, `ME_CSR_HA=0xc`, `H_D0I3C=0x800`) є ключовими. У MINIX 3 ми будемо звертатися саме до цих зміщень відносно BAR0.

## 4. Вимоги до емулятора (EMULATED VIEW)

Для тестування драйверів у `wsm-os / qemu-uefi-selftest.sh` емулятор повинен відповідати наступному контракту:
1. **PCI ID:** Експонувати пристрій `Vendor=0x8086`, `Device=0xa13a`.
2. **MMIO BAR0:** Виділити пам'ять, яка перехоплює читання/запис.
3. **Регістри:** При читанні `ME_CSR_HA [0xc]` емулятор має повертати `0x8000000b` (ME Ready).
4. **Дані:** При отриманні байтів MKHI-запиту емулятор має відповісти зафіксованими байтами з секції 2.
