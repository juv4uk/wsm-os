# Стохастична машина: аналогове обчислення через фізичний шум

**Дата:** 2026-09-20  
**Статус:** дослідницька нотатка / research note  
**Контекст:** продовження `SUBTHRESHOLD-PHYSICAL-CONSTANTS.md`  
**Питання:** наскільки часто можна читати фізичний шум і чи можна отримати щось на кшталт аналогової машини?

---

## Реальна пропускна здатність фізичного шуму на i5-6400

```
RDSEED  (сирий апаратний шум)         →  ~1 MB/s
         повільно, але справжня ентропія — без DRBG між шумом і результатом

RDRAND  (DRBG на основі шуму)         →  ~50–100 MB/s
         швидше, але вже оброблено генератором псевдовипадкових чисел

MSR тепловий датчик (IA32_THERM_STATUS) →  ~10–100 Hz
         дуже повільно, але це реальна T кристалу — kT/q без посередника

RDTSC jitter між ядрами               →  ~200 M читань/с
         непряме — відображає теплові варіації тактової частоти
```

**Головна асиметрія:** тепловий шум транзистора широкосмуговий (до ГГц),
але цифровий інтерфейс читає його вузькою щілиною.
Це як пити океан через трубочку.

## Чи можна побудувати справжню аналогову машину на x86?

### Шлях 1 — Емуляція через швидку вибірку

```
RDRAND + RDTSC jitter + XOR → потік бітів що поводиться як неперервний сигнал
```

Це **не аналог**. Це дрібна дискретизація з фізичним джерелом.
Результат детермінований між двома вибірками — просто дуже дрібний крок.

### Шлях 2 — Справжній аналог (не на x86)

Субпорогова зона + **не оцифровувати вихід** = справжня аналогова операція.
Саме так працює нейроморфне обчислення:

```
IBM TrueNorth  → 4096 нейронів, кожен субпороговий транзистор
Intel Loihi    → провідність мемристора = "вага" нейрона,
                 змінюється аналогово, не ступінчасто
```

На звичайному x86 — неможливо. Апаратура форсує 0/1 на кожному рівні.

## Стохастичне обчислення — третій шлях

Між "дискретна машина Тюрінга" і "справжній аналог" є проміжна модель:
**stochastic computing**.

### Принцип

Числа представлені не як біти позиційної системи,
а як **ймовірність одиниць у бітовому потоці**:

```
0.75  →  11101110111011...  (75% одиниць у потоці)
0.25  →  00010001000100...  (25% одиниць у потоці)
```

### Арифметика стає тривіальною

```
Множення   =  AND між двома потоками
               P(A AND B) = P(A) · P(B)  ✓

Додавання  =  MUX з випадковим бітом вибору S:
               out = S ? A : B
               E[out] = 0.5·A + 0.5·B  ✓

Середнє    =  OR між двома потоками
```

Жодних переносів, жодного carry-propagation — операції над числами
стають операціями над ймовірностями.

### Джерело випадковості = фізичний шум

```
RDRAND → стохастичний потік → арифметика → результат
```

Коли джерелом рандомності є `RDRAND` (апаратний шум транзисторів),
обчислення **містить в собі стан фізичного світу** в момент виконання.

**Два однакові виклики дадуть різні відповіді** залежно від температури
кристалу, рівня шуму, квантових флуктуацій у момент читання.

Це вже не детермінована машина Тюрінга.

## Що це означає для wsm-os

### Нова форма запиту до залізо

```
Класичний wsm-os запит:
  "чи може залізо виконати операцію X?"

Стохастичний wsm-os запит:
  "чи може залізо виконати операцію X так, щоб результат
   містив поточний фізичний стан кристалу?"
```

### Властивості стохастичного wsm-обчислення

| Властивість | Детермінований wsm | Стохастичний wsm |
|---|---|---|
| Відтворюваність | повна | відсутня |
| Фізичний стан у результаті | ні | так (через RDRAND) |
| Точність | точна | пропорційна довжині потоку |
| Складність операції | O(n бітів) | O(1) gate |
| Машина Тюрінга? | так | ні |

### Точність vs швидкість

```
Потік 8 бітів    →  точність ~1/8   (~12%)  але швидко
Потік 256 бітів  →  точність ~1/256 (~0.4%) повільніше
Потік 1024 бітів →  точність ~1/1024 (~0.1%) повільно
```

Точність масштабується як `1/√N` де N — довжина потоку.
Це **аналог-цифровий компроміс** без зміни апаратури.

## Практичний експеримент для wsm-os

```asm
; Читаємо фізичний шум і будуємо стохастичне число 0.75
; (750 одиниць із 1000 спроб ≈ 0.75)

xor ecx, ecx          ; лічильник одиниць
mov edx, 1000         ; довжина потоку

.loop:
  rdrand rax          ; фізичний шум → rax
  and rax, 1          ; беремо молодший біт
  add ecx, eax        ; рахуємо одиниці
  dec edx
  jnz .loop

; ecx / 1000 ≈ реальне число з фізичним шумом всередині
```

Цей фрагмент — не генерація випадкового числа.
Це **вимірювання** фізичного стану транзисторів у момент виконання,
представлене як раціональне число.

   таку що результат залежить від фізичного стану машини в момент виклику?

   щоб температурна залежність `kT` була вимірювана між двома викликами?

4. Чи детермінований `wsm-os` milestone може мати стохастичний варіант
   як окремий, паралельний архітектурний домен?
